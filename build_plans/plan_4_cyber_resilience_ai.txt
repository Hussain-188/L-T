================================================================================
BUILD PLAN: CyberSentinel — AI-Driven Cyber Resilience System
================================================================================

1. PROJECT OVERVIEW
--------------------------------------------------------------------------------
An AI-powered security operations proof-of-concept that ingests network traffic
data, detects threats using machine learning, triages alerts with an AI agent,
maps detections to MITRE ATT&CK, and orchestrates response actions with
human-in-the-loop governance for high-impact decisions.

4. MODULE BREAKDOWN
--------------------------------------------------------------------------------

Module 1: Data Ingestion and Feature Engineering
  - Load CIC-IDS2017 CSV files (labeled network flows)
  - Parse 80+ features: flow duration, packet counts, byte counts,
    flag counts, inter-arrival times, header lengths, payload stats
  - Additional engineered features:
    - Payload entropy (detect encrypted/obfuscated traffic)
    - Flow rate ratios (bytes/packets per second)
    - Port behavior patterns (unusual port combinations)
    - Temporal patterns (time-of-day, burst detection)
  - Real-time simulation mode: replay flows at configurable speed
  - Normalize and scale features for ML models
  Files: ingestion/loader.py, ingestion/features.py, ingestion/simulator.py

Module 2: Detection Engine
  Supervised Component:
  - XGBoost classifier trained on labeled CIC-IDS data
  - Random Forest as secondary classifier
  - Ensemble: weighted vote of both classifiers
  - Multi-class: benign, brute force, DoS, web attack, infiltration,
    botnet, port scan, DDoS
  - Output: predicted attack type + confidence probability

  Unsupervised Component:
  - Autoencoder neural network trained only on benign traffic
  - Reconstruction error as anomaly score
  - Catches novel attacks not in training labels
  - Threshold tuned on validation set

  Alert Generation:
  - Combine supervised + unsupervised signals
  - Assign severity: low/medium/high/critical
  - Deduplicate: suppress identical alerts within time window
  Files: detection/ensemble.py, detection/autoencoder.py,
         detection/alert_generator.py

Module 3: AI Triage Agent
  - Receives stream of alerts from detection engine
  - Clustering: group related alerts by source IP, time window,
    attack pattern into incident clusters
  - For each incident cluster:
    - Summarize what happened in natural language
    - Identify affected systems and scope
    - Estimate severity based on target criticality
    - Map to MITRE ATT&CK techniques using technique descriptions
    - Recommend ranked response actions
  - Uses LLM (via LangChain) with structured prompts
  - Operates within guardrails: cannot execute actions, only recommends
  Files: triage/agent.py, triage/clustering.py, triage/mitre_mapper.py,
         triage/prompts.py

Module 4: MITRE ATT&CK Mapper
  - Load MITRE ATT&CK Enterprise matrix (STIX format)
  - Map detected attack types to ATT&CK techniques:
    - Brute Force -> T1110 (Brute Force)
    - Web Attack -> T1190 (Exploit Public-Facing Application)
    - Port Scan -> T1046 (Network Service Scanning)
    - Lateral Movement -> T1021 (Remote Services)
    - DDoS -> T1498 (Network Denial of Service)
  - Generate ATT&CK heat map showing which tactics/techniques are active
  Files: mitre/mapper.py, mitre/stix_loader.py

Module 5: Response Orchestrator
  - Policy engine defines action tiers:
    Tier 1 (Auto): Block external IP, rate limit connection
    Tier 2 (Notify): Alert analyst, log for review
    Tier 3 (Approve): Isolate host, disable account, trigger forensics
  - For Tier 3 actions:
    - Package evidence: alert details, triage reasoning, confidence
    - Send to human approval interface
    - Wait for approve/reject/modify decision
    - Execute approved action (simulated in POC)
  - All actions logged with timestamp, actor, justification
  Files: response/orchestrator.py, response/policies.py,
         response/actions.py

Module 6: Dashboard
  Pages:
  a) Overview
    - Active alerts count by severity
    - Detection rate over time (line chart)
    - Top attacking IPs and targets
    - System health indicators

  b) Alert Feed
    - Real-time scrolling alert list
    - Filter by severity, attack type, source
    - Click to expand: full details, features, confidence

  c) Incident View
    - Clustered incidents with timeline
    - Triage agent's narrative and recommendations
    - Response action status

  d) MITRE ATT&CK View
    - Heat map of the ATT&CK matrix
    - Color intensity = frequency of detections per technique
    - Click technique to see associated incidents

  e) Human Approval Queue
    - Pending high-impact actions
    - Evidence package for each
    - Approve / Reject / Modify buttons
    - Countdown timer for time-sensitive decisions

  f) Audit Trail
    - Searchable log of all detections, decisions, actions
    - Exportable for compliance reporting

  Files: frontend/src/pages/ (Overview, Alerts, Incidents, MitreMap,
         Approvals, AuditLog)

Module 7: Rule-Based Baseline (for Comparison)
  - Simple threshold rules:
    - Flag if packets/sec > threshold
    - Flag if connection to known-bad port
    - Flag if failed login count > N
  - Same alert format as ML system
  - Run on same test data
  - Compare: detection rate, false positives, MTTD, MTTR
  Files: baseline/rule_engine.py, baseline/rules.yaml
